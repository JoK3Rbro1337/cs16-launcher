# CS 1.6 Launcher — архитектура и план реализации

Полноценный лаунчер для лицензионной копии Counter-Strike 1.6: обёртка над игрой + автообновление кастомного контента сборки + браузер серверов + Windows/Linux.

## 1. Стек

Тот же, что в kadr-forge — максимум переиспользования опыта и конфигов:

- **Electron + electron-vite + React + TypeScript**
- **electron-builder** — паблишинг под Win/Linux
- **electron-updater** — самообновление *лаунчера* (не игрового контента), провайдер GitHub Releases
- IPC строго через `contextBridge` в preload, без `nodeIntegration` в renderer

## 2. Архитектура процессов

Main process (Node.js, доступ к FS/сети/дочерним процессам) делится на 4 независимых модуля:

- **steam-detect** — поиск Steam и установленной CS 1.6
- **content-sync** — синхронизация кастомного контента (скины/конфиги/карты)
- **launch** — оркестрация запуска через `steam://`
- **server-browser** — опрос серверов

Renderer (React) — чистый UI, общается с main только через IPC.

## 3. Детект Steam и установленной игры

Кроссплатформенная логика, разница только в первом шаге:

- **Windows**: путь Steam из реестра `HKCU\Software\Valve\Steam` (значение `SteamPath`), фолбэк — `HKLM\SOFTWARE\WOW6432Node\Valve\Steam`
- **Linux**: обычно `~/.steam/steam` или `~/.local/share/Steam`
- Дальше одинаково: читаем `steamapps/libraryfolders.vdf` — там список всех библиотек (диск может быть не один)
- В каждой библиотеке ищем `steamapps/appmanifest_10.acf` (**10** — appid Counter-Strike) — оттуда `installdir` даёт реальный путь установки

Готовые npm-пакеты, закрывающие большую часть этого:

- `steam-path` — находит Steam, парсит `libraryfolders.vdf`, отдаёт манифест по appid одним вызовом
- `vdf-parser` — если нужен низкоуровневый контроль над парсингом VDF/ACF

**Референс**: опенсорсный лаунчер `iw4x/launcher` реализует ровно эту логику (VDF/ACF-парсинг, поиск библиотек, минимизация докачки за счёт уже существующих файлов). Написан на C++, но структура переносится 1:1.

## 4. Контент и автообновление сборки

Манифест-система, полностью отдельная от самообновления лаунчера (то — `electron-updater`, это — свой код).

**Схема манифеста** (хостится на любом статическом CDN — R2/S3/даже GitHub Releases для небольших сборок, лимит там ~2GB на файл):

```json
{
  "version": "1.4.2",
  "files": [
    {
      "path": "cstrike/sound/weapons/deagle-1.wav",
      "sha256": "a1b2c3d4...",
      "size": 123456,
      "url": "https://cdn.example.com/content/1.4.2/cstrike/sound/weapons/deagle-1.wav"
    }
  ]
}
```

**Логика клиента**:

1. Скачать `manifest.json` с CDN
2. Для каждого файла посчитать хэш локальной копии (sha256 — надёжно, либо size+mtime — быстрее, но менее строго)
3. Несовпадения/отсутствующие файлы — в очередь докачки: параллельно, с лимитом потоков, с возможностью резюма после обрыва
4. Опционально strict-mode: файлы вне манифеста, но присутствующие локально — предлагать удалить (чистота сборки)

## 5. Запуск игры

**Главное архитектурное решение**: не реализовывать Proton-обвязку руками — делегировать запуск самому Steam.

| Способ | Когда | Заметки |
|---|---|---|
| `steam://connect/ip:port` | Клик «подключиться» в браузере серверов | Steam сам определяет игру по ответу сервера. Одинаково работает на Win/Linux |
| `steam://rungameid/10` | Просто «Играть» без конкретного сервера | Использует launch options, уже заданные в самом Steam |
| Прямой запуск бинарника + ручной Proton-wrapper | Не рекомендуется | Хрупко: нужно самим таскать `STEAM_COMPAT_DATA_PATH`, версии Proton. А на Linux у CS 1.6 есть ещё и нативная ветка — дублировать логику выбора native/Proton, которую Steam и так умеет, не стоит |

appid Counter-Strike (1.6) = **10**.

## 6. Браузер серверов

GoldSrc/Source query protocol (`A2S_INFO` / `A2S_PLAYER` / `A2S_RULES`) по UDP, порт обычно 27015.

Готовые npm-пакеты:

- `source-server-query` — TS, поддержка всех трёх типов запросов
- `steam-server-query-goldsrc-support` — отдельно учитывает отличия формата ответа у GoldSrc от обычного Source, плюс умеет опрашивать **мастер-сервер Steam** по appid — можно получить список вообще всех публичных CS 1.6 серверов, а не только свой захардкоженный список избранных

Флоу: список избранных/с мастер-сервера → пинг/карта/игроки → кнопка «подключиться» → `steam://connect/ip:port`.

## 8. Дорожная карта

| Веха | Что делаем |
|---|---|
| M0 | electron-vite + React + TS скелет, конвенции как в kadr-forge |
| M1 | steam-detect: находим путь установки CS 1.6 на Windows и Linux |
| M2 | launch: кнопка «Играть» через `steam://rungameid` |
| M3 | content-sync: схема манифеста, хэш-диффинг, очередь докачки, UI прогресса |
| M4 | server-browser: опрос избранных + мастер-сервера, сортировка по пингу, «подключиться» |
| M5 | electron-updater + electron-builder паблишинг под обе платформы |
| M6 | ретема/брендинг под свою сборку |

## 9. Что перепроверить в процессе реализации

- Реальное поведение `steam://run//args` на актуальной версии Linux-клиента Steam (баг из трекера Valve мог быть уже исправлен к моменту разработки)
- Нужна ли принудительная поддержка переключения native/steam_legacy, или полагаемся на то, что пользователь сам выбрал ветку в Steam
- Точный формат A2S-ответа у GoldSrc-серверов местами отличается от чистого Source — тестировать на реальных CS 1.6 серверах, не только по документации
